# Harbor

**A systemd-like service manager for HarmonyOS PC, built as a tiny pure-ArkTS HAP (~136 KB).**

Harbor runs background services (mihomo, magpie, or any signed ELF) inside its own app sandbox, so they survive closing the terminal or hiding the window. It reads standard **systemd `.service` units** (e.g. those generated by Homebrew), offers a **real status-bar tray** icon (close = hide to tray, click = restore), and exposes a `brew services`-style CLI over a token-authenticated loopback IPC.

## Why

On HarmonyOS PC, processes are reclaimed by **cgroup, not parentage**. `setsid nohup` reparents a process to init (PPID=1) but leaves it in the launching app's cgroup — closing that app kills it. Harbor hosts services in **its own** cgroup, so they are independent of the terminal. There is no systemd/launchd on this platform, so Harbor reimplements the useful subset: service discovery from `.service` units, start/stop/restart, status, `keep_alive` watchdog, and cron/interval timers.

## Features

- Reads systemd `.service` units (`ExecStart`, `Environment`, `StandardOutput=append:`) or direct `exec` entries
- Real tray: closing the window calls `hideAbility()` (window gone from taskbar, process alive); tray click restores it
- Token-authenticated loopback IPC (`AUTH <token> <cmd>`), token in `~/.config/harbor/bridge.conf`
- `keep_alive` watchdog with retry backoff; cron (`OnCalendar`) and interval (`OnUnitActiveSec`) timers
- Boot autostart via the system Settings → App startup manager, with `autoHideOnLaunch` to hide silently

## CLI

```sh
harbor                                   # list (default)
harbor list
harbor start mihomo / stop mihomo / restart mihomo
harbor status mihomo
harbor info mihomo
harbor discover                          # scan installed brew .service units
harbor discover --add zellij            # add one to apps.json (stable opt/ path)
harbor set-timer mihomo cron '*-*-* 03:00:00'
harbor set-timer mihomo interval 3600
harbor set-timer mihomo off
harbor set-autohide true                 # hide to tray on launch (boot autostart)
harbor cleanup / reload / ping
```

## Config

`~/.config/harbor/apps.json`:

```json
{
  "autoHideOnLaunch": true,
  "apps": [
    {
      "name": "mihomo",
      "type": "unit",
      "unit": "/storage/Users/currentUser/.harmonybrew/opt/mihomo/sh.brew.mihomo.service",
      "pidfile": "/data/storage/el2/base/cache/harbor/mihomo.pid"
    }
  ]
}
```

- `type: unit` — reads a `.service` file; `type: exec` — direct `bin`/`args`/`env`/`log`.
- `pidfile` is required and unique per service (lives in the HAP sandbox cache).
- `timer`: `{ "type": "calendar", "onCalendar": "*-*-* 03:00:00" }` or `{ "type": "interval", "onUnitActiveSec": 3600 }`.

## Build & install

```sh
bash build-all.sh
```

`build-all.sh` compiles the native NAPI bridge (`build-so.sh`), builds the HAP with hvigor + the HMS SDK (for `@kit.StatusBarExtensionKit`), injects the `.so`, then signs/installs with `app-installer` using your local debug profile. Environment overrides: `HARBOR_CLT` (default `/opt/electron-ohos-clt`), `HARBOR_SDK`, `HARBOR_HVIGOR`, `HARBOR_SIGN_PROJECT`.

Requirements: HarmonyOS PC with HMS, Homebrew `app-installer` / `ohos-sdk`, and a dev debug profile with `CUSTOM_SANDBOX` + `READ_WRITE_USER_FILE` ACLs.

## Architecture

- **ArkTS HAP** — UIAbility, status-bar tray (`statusBarManager`), loopback `TCPSocketServer`, 10s/30s scheduler
- **Native NAPI bridge** (`harbor_bridge.c`, pure C) — `fork + setsid + fork + execve`, pidfile dedup via `kill(pid,0)`, `killAndWait`, env injection. Linked with `libace_napi.z.so`, `-Wl,-z,global` for OHOS dlopen namespace.
- **CLI** (`harbor`, Python) — reads the same token file, sends `AUTH <token> <cmd>` over TCP.

Design spec + validation evidence: `openspec/specs/ohos-brew-services.md` in the workspace repo.
